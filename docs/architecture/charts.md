# Charts (crates/chart)

Status: first slice. Clean-room: rules come from Excel's observable answers via COM, never from Microsoft code.

## Layers
- `crates/xlsx/src/drawing.rs`: read-only `Workbook::sheet_charts`, anchors (two-cell, one-cell, absolute), `Anchor::rect_pt`.
- `open365-chart::ChartSpace`: typed view over the lossless XML tree of `c:chartSpace`; `to_bytes` writes the tree back, so unknown elements survive. Typed: bar/column (clustered, stacked, 100%), line, area, pie, doughnut, scatter; series refs and caches, titles, legend, axes, data labels, manual layout.
- `resolve` + `CellSource`: values from the workbook's stored cells (`WorkbookCells`) or any source (calc engine later); falls back to the cache.
- `render` gives a `DisplayList` (rects, paths, text runs with font and size) at the anchor size. Text is measured through `TextMeasure`; tests use bundled Carlito (Calibri-compatible).

## Oracle (tools/office/chart-oracle.ps1)
Own Excel instance, AutomationSecurity=3, quit in `finally`. Modes: `-Fixtures`, `-Layout`, `-Axes [-Seed n]`, `-Sweep`.
Fixtures force the chart font to Calibri: the 2023 theme default (Aptos Narrow) cannot be bundled.

## Axis scaling (crate::axis)
Matched exactly (1e-9 relative) on the 306-case generated corpus plus 40 scatter X axes, and on the 780-case plot-size sweep. Rules are in the module docs. Limits: the interval budget was fitted to these data; log axes, date axes and partially fixed axes are not verified; 10 pt text only was measured (other sizes scale linearly, unverified). The budget is worked on the plot area's OUTER rectangle, see Round 5.

## Layout
`tests/layout_fixtures.rs` compares plot inside/outer, legend and title rectangles at +-1 pt: 10 fitted fixtures 140/140, 3 later fixtures (`chart-holdout-*`) 44/44 after one refit of legend constants (first, un-refitted pass: 31/44, so those constants are in-sample now). Not covered: manual layouts, overlay legends, multi-line titles, rotated labels, data-label collisions, long category labels (no wrapping/rotation), combo charts, secondary axes, 3-D and other chart types.
Coordinates: Excel reports rectangles in a chart area 5 pt smaller than the object; the display list uses those coordinates 1:1 (assumption, not pixel-verified).

## Model, edits, builder, style parts (session 2)
- Groups: bar/column, line, area, pie, doughnut, scatter plus `Bubble`, `Radar`, `Stock` (typed fields: `bubble_scale`, `size_represents`, `radar_style`, `hi_low_lines`, `up_down_bars`). Combo charts are several groups; `PlotArea::is_combo` and `secondary_groups` tell them apart. Rendering of a secondary axis is NOT done: every group uses the first group's value axis (open).
- Series: `trendlines` (`Trendline`, all six kinds with order, period, forward/backward, intercept, R^2/equation flags), `error_bars` (`ErrorBars`, fixed/percentage/stdDev/stdErr/custom), `bubble_sizes`. Trendlines and error bars are parsed but not drawn yet.
- `ChartSpace::style_id` reads `c14:style` / `c:style`. `ChartStyle` and `ColorStyle` parse `xl/charts/styleN.xml` and `colorsN.xml` (`cs:` namespace) as lossless trees. Excel 20430 saving through COM writes neither part, so these two are tested on hand-written XML only. `crates/xlsx` does not expose the chart's style/colors relationships: it would need to hand them out next to `chart_part` (report, not edited).
- Lossless: `to_bytes` is byte-identical to the input for every Excel fixture and for hand-written parts (tests assert bytes, not just the tree). Typed edits (`set_title_text`, `remove_title`, `set_legend_position`, `remove_legend`, `set_axis_scale`, `clear_axis_scale`) write into the tree in schema order; undoing every edit restores the original bytes.
- `ChartBuilder` makes a new part for 17 kinds (column/bar/line/area in all groupings, scatter, bubble, pie, doughnut, radar, stock, log value axis). Output reads back through `ChartSpace::parse` and renders.
- Render draws stock like a line chart, bubble as sized circles (largest = 25 % of the shorter plot side at 100 %, unverified) and radar as a web (no spoke labels, unverified).

## Axis scaling beyond the linear value axis
`tools/office/make-chart-corpus.ps1` records generated corpora from Excel (own instance, aborts if it attached to a running one, AutomationSecurity 3, Quit in finally) into `fixtures/reference/xlsx/chart-scale/`. Seed 1001 is train (fitted on), seed 2002 hold-out.
- Linear value axis: 346/346 on `axes.json` (train) and 346/346 on `axes-seed7.json` (hold-out, recorded earlier, now asserted).
- Log value axis (`axis::log_scale`, `log_max_intervals`): the axis always contains 1; min = `base^floor(log lo)` capped at 1; max = `base^ceil(log hi)` floored at 1; major = `base^k` for the smallest k with `ceil(decades/k)` <= `floor((len - 0.9 f)/(1.2207 f))` (no cap at 10; the `0.9 f` term drops when the axis reaches below 1 because category labels then sit in the plot); minor = major. Train 300/300. First hold-out pass (before the budget was refitted with the 30-interval case) 148/150; after the refit 149/150 on the same hold-out set, so that set is now partly in-sample. The remaining miss: a scatter whose data sit in one decade at 1.4e6..9.5e6 and Excel starts the axis at 1e6, not 1. `-Set lognarrow` records that regime (files land in `chart-scale/lognarrow-*.json`); no rule is fitted yet.
- End to end through `ChartBuilder` + `render` (our own plot height): 299/300 train, 149/150 hold-out. The miss is a plot height 0.09 pt on the wrong side of the budget boundary (`CAT_LABEL_PAD_H` is fitted to +-1 pt only).

## Layout corpus (open)
`tests/layout_corpus.rs` replays `chart-scale/layout-{train,holdout}.json` (random type, size, legend, titles, series, categories; plot inside/outer, legend, title rectangles and the value axis). It skips until the files exist. The recording is slow (about 2 s per chart under load) and was still running when this was written; the floors in the test are 0 until the first measured run sets them. Date axes: `-Set date` recorded `date-train.json` (300) and `date-holdout.json` (150). Reading them: base unit is the smallest gap in the data (days 0, months 1, years 2); min and max snap to the month or year boundary of the first and last date for month and year base units (day base: exact first and last date); the major unit scale follows the base unit and the count depends on the plot width. No rule or replay test exists yet.

## Round 5: interval budget, pie label text (session 5)
Interval budget of the linear value axis (`axis::max_intervals`), found by testing the budget against several lengths of the same charts: it follows the plot area's OUTER rectangle (`PlotArea.Width/Height`, the inside rectangle plus the category labels as they actually come out), not the inside rectangle.
- Vertical axis: `N = floor(outer / (1.2207 f) - 2)` (f = tick label size; 2 x line height of margin). With Excel's outer height: 1087/1087 train and 424/424 hold-out column/line/area cases, no free parameter besides the 24.41 = 2 lines constant (feasible 24.41..24.52 at slope 12.207). Against the inside height it missed 38 of 858 cases: labels that wrap or rotate change the inside height but not the budget (cases #57, #134, #96).
- Horizontal axis (bar): `N = floor(outer / (3.82 f))`; feasible 38.0..38.3 pt per interval. Train narrow-label bars all match, hold-out 424/424 together with the vertical ones (`tests/axis_corpus.rs`, `interval_budget_follows_the_outer_plot_rectangle`). The sweep (inside width only) is consistent when its category-label region is 6..31 pt (10 pt assumed); scatter X axes use outer = inside + widest Y label + gap + half of the last X label.
- Our own layout reproduces this because the auto path already knows `o.height`/`o.width`; a user-fixed inner plot rectangle keeps the surroundings of the auto layout (assumption, not measured).
- Rates: labels `tick_text` train 96.7 -> 99.4 %, hold-out 98.1 -> 99.1 %, second hold-out (seed 3003, recorded after the rule, 300 cases) 99.3 %; layout corpus `value_axis` train 95.1 -> 98.2 %, hold-out 94.7 -> 97.7 %.
- Open: a horizontal axis whose labels have six or more digits (1,000,000, 2.00E+06, 1,800K) is given more room than 38.2 pt per interval (cases #10, #60, seed 3003 #102 and #182; `layout-*.json` bars with 7-digit ticks). A "spacing >= widest label" test fits the layout corpus labels but costs more than it wins on formatted axes (Excel does not measure the formatted text), so it is not in the code. `column_percent` with negative data (axis -1..1, step 0.2) and long titles that wrap are separate layout misses.
Pie data labels: with the percentage shown too, a custom label number format belongs to the percentage and the value keeps its cell format (`Gamma, 4340209%, 0.227`); a percentage in `General` reads as `0%`. `label_text.pie` is now 100 % on all three label corpora (the overall label_text rate was 99.6 % on train). Pie label positions: `inside_end` (32 % train) and `best_fit` (13.7 % train, 7.7 % hold-out) are still open. Findings: Excel's inside-end label centre lies exactly on the radial line through the slice middle (perpendicular offset 0.0 in 117 labels) while our formula pulls x and y back by different amounts, so it is off the line; the pull-back is not linear in width/height, not a corner touching a circle, not an ellipse extent (rms 3 to 6 pt for each); sizes come out right, positions of `best_fit` also carry Excel's own sub-point rounding of label rectangles (heights alternate 13.5/14.2). The in/out choice of `best_fit` is `sweep * 0.82 r >= width` for all but a handful of labels.
